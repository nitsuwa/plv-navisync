## Status and evidence rules

Every checklist case begins NOT RUN. Allowed results: PASS, FAIL, BLOCKED, NOT RUN. FAIL means executed and differed from the expected behavior; BLOCKED names the exact prerequisite. Unsupported functionality is not silently skipped: report the acceptance gap without adding it.

PASS requires all listed steps and assertions, a screenshot where appearance matters, persistence check where specified, and console/network review. A screenshot alone does not prove saving, permission enforcement, or publication. Automated suites do not substitute for browser evidence. Record UI, UI+READBACK, EMULATED, API-FIXTURE, or PHYSICAL evidence type.

For each case record: ID/subcase, commit, time/timezone, role, viewport/theme/input, fixture alias, exact actions, expected/actual result, status, screenshot/log links, cleanup state. Split subcases if some pass and others fail/block. Maintain NOT RUN cases explicitly; do not mark a parent PASS until all mandatory subcases pass.
